## ハンズオンでの使い方

1. CPUエディターにある8命令の空欄（`;` の前）へ処理を書きます。初期ROMで使わない **MOV B, Im / MOV A, B / MOV B, A / IN A** は記入済みです。
2. 各命令の「テスト」、または「すべての命令をテスト」を押します。失敗時は実行前の状態・命令・入力と、期待値／実際の次状態を比較できます。
3. 「実行」で、編集したCPUにROMを実行させます。LED、A/B、CF、PC（コードでは `ip`）、実行した命令と履歴が変わります。
4. 停止・再開・リセット・速度変更・入力スイッチを使って観察します。ROMもSystemVerilogで書き換えられます。

1命令ずつ進める操作はありません。未完成のCPUもそのまま実行できます。テストと実行の両方で参加者のコードを利用して評価します。

コードは同じブラウザに自動保存されます。「保存用JSON」で持ち出し、「読み込む」で復元できます。CPU・ROMの `.sv` もダウンロードできます。ブラウザのデータ削除や別端末への移動に備え、終了時にJSONを保存してください。CPUを書き換えると以前のテスト結果と実行状態を消去し、ROMを書き換えると実行状態をリセットします。

## CPUと初期ROM

初期データは `code/td4/cpu.sv` と `code/td4/rom.sv` からビルド時に読み込みます。CPUの完成例から演習部分を空欄にします。初期ROMはスイッチをBへ取り込み、LEDへ表示し、待ち時間を挟んで加算します。Bの桁上がり後は全消灯／全点灯を繰り返します。

今回のCPUファイルを基準に、非加算命令のCFは0、JNCは実行前のCFを参照、PCとレジスタは4bitで折り返す動作です。未定義opcodeは共通処理だけを行います。

CPUの命令コード信号名は `opcode` に統一しています。ダウンロード用CPUでは、元ファイルにあるポート末尾の `led;` を `led` に補正します。

## 対応するSystemVerilog

**演習に必要な構文を実装した専用インタープリターです。汎用のSystemVerilogコンパイラではありません。** ソースを字句解析・構文解析し、ビット幅を考慮して評価します。JavaScriptの `eval` / `Function` は使用しません。

対応内容:

- `always_comb`、`begin/end`、ブロッキング代入 `=`、`if/else`、`case` / `unique case` / `default`
- 既定の信号、2/8/10/16進数の定数、符号付き定数、`'0` / `'1`
- 連結、右辺の信号の定数ビット選択・範囲選択、括弧、三項演算子
- `+ - * ~ ! & | ^ == != < > <= >= && || << >>`
- 代入先の幅による演算幅の拡張、連結内の式の幅、4bitへの切り捨て
- ROMの配布形式の `module rom(...)`、または `always_comb` 単体

追加の信号宣言、配列、ループ、関数、遅延、X/Z、非ブロッキング代入、左辺の部分選択には対応しません。未対応の記述はエラーになります。CPUの全 `next_*` とROMの `data` は実行経路上で代入が必要です。初期化前の次状態の参照や `unique case` の複数一致もエラーにします。これは0/1の値と命令境界の状態を扱う環境で、ゲート遅延やハザード、ラッチのシミュレーションは行いません。

1ファイル20,000文字までです。コードの複雑さ・入れ子・処理量にも上限があり、命令テストは30秒、実行準備は5秒で打ち切ります。

## 検証

- 各命令を1,024ケースで検証します。即値・入力・A/B・CFの値、PCの折り返し、対象外のレジスタが保持されることを確認します。全状態の直積を網羅する形式検証ではありません。
- Vitestで完成例、参考4命令、誤実装の検出、CFとジャンプ、初期ROM、構文と演算幅を検証します。
- Playwrightで編集・個別／一括テスト・ROM変更・連続実行・停止／再開・保存／復元・モバイル表示を検証します。
- `tests/icarus.spec.ts` は、旧検証用WASMがローカルにある場合に4,096件のCPU次状態と30個の式をIcarus Verilogと照合します。旧資産のないCIではこの追加検証をスキップします。WASMはテスト内だけで読み込み、公開物には含めません。

## 構成

| 場所 | 内容 |
| --- | --- |
| `src/App.tsx` / `src/Editor.tsx` | 画面、編集、保存 |
| `src/sv.ts` | 対応構文の解析・評価 |
| `src/td4.ts` | 演習雛形、CPU・ROM、命令テスト |
| `src/lab.worker.ts` | テストと連続実行 |
| `code/td4/` | 講義用CPU・ROM |
| `old/` | 旧設計・旧アプリ・技術検証の保管先 |

依存ライブラリの著作権・ライセンス表示はビルド時に `public/third-party-notices.txt` に生成し、公開ファイルに同梱します。

## ローカル起動

Node.js 24を使用します。

```sh
npm ci
npm run dev
```

表示されたURLの **`/KC3-2026-cpu/`** を開きます（通常 `http://127.0.0.1:5173/KC3-2026-cpu/`）。Windowsでは `./scripts/dev.ps1` でも起動できます。このスクリプトはPATHにNode.jsがなければ、既存の `old/.tools/node-v24.21.0-win-x64` も探します。

```sh
npm test
npm run build
npm run preview
npm run test:e2e
```

ローカルのブラウザテストにはGoogle Chromeを使用します。CIではPlaywrightのChromiumを使用します。`LAB_URL` を設定すると、起動済みのサーバーや公開サイトに対してブラウザテストを実行できます。
